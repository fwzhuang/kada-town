# 关卡设计与实现约定

游戏围绕「观察 → 摆放 → 预测 → 运行 → 找到问题 → 修改」展开。道路和机关服务于豆豆修复小镇的任务；主线不依赖手速，没有倒计时、生命值或失败次数惩罚。

## 数据与规则

坐标使用列字母与从 1 开始的行号，如 `B3`。引擎内部方向依次为上、右、下、左，即 `0, 1, 2, 3`。直路基础方向为左右，弯路基础方向为上右，`rotation` 表示顺时针旋转次数。

`src/levels.js` 中的 `make()` 从标准路线推导道路类型、朝向、零件数量与可铺格子，再添加固定道路、干扰路线和额外零件。

| 字段 | 含义 |
| --- | --- |
| `id` / `chapter` / `name` / `story` | 关卡编号、章节、名称与关内对白 |
| `size` | 正方形棋盘边长 |
| `start` / `startDirection` / `goal` | 起点、初始行进方向、终点 |
| `placeable` / `fixed` | 可铺格子与固定道路 |
| `mechanisms` | 按钮、桥、物品、门、箭头和传送环 |
| `inventory` / `par` | 可用零件数量与二星道路目标 |
| `requiredItems` / `requiredCheckpoints` | 终点任务条件与必经机关 |
| `solution` / `path` | 用于验证的标准布局与路线 |

单步规则由 `advance()` 执行。它校验道路入口、前置条件及必经任务，返回状态、事件或具体失败原因。`simulate()` 在没有 DOM 的情况下完整运行关卡，用于自动验证。界面仅根据事件展示按钮按下、桥展开、拾取和庆祝。

## 难度安排

前 12 关逐关介绍道路摆放、旋转、固定路、多余零件、按钮、小桥、齿轮与有限零件。后四章使用路线与方向模板，逐步增加多组机关、钥匙、单向路和传送。每章的开头保留少量富余零件，末段收紧资源。

增加难度时优先调整选择和顺序，而非延长操作时间。干扰路线应能给出可理解的失败原因。章节转换通过来信、邮袋、邀请函和纸飞机串联，各章完成后解锁剧情结尾。

## 原设计一致性修正

原始 V1.0 设计中部分坐标、标准路线和零件数量存在冲突。实现保留教学意图，作出以下修正：

- 第 4 关列出的路线实际上只需要 4 块道路。
- 第 5 关 D3 为上方入口、右侧出口的固定弯桥。
- 第 6–7 关小桥位于 D2，为必经任务；需要先经过 B1 按钮。
- 第 8–9 关补全齿轮位置与终点之间的连接。
- 第 10–12 关依据可运行路线重新计算零件数量。

### 第 6 关示例

路线为 `A3 → B3 → B2 → B1 → C1 → D1 → D2 → D3 → E3`。先经过 B1 按钮，再通过 D2 固定桥。玩家摆放 B3 左上弯、B2 竖直路、B1 下右弯、C1 水平路、D1 左下弯、D3 上右弯。

## 扩展检查

新增或修改关卡后，验证所有坐标在边界内、标准路线不重复、库存足够、所有齿轮可获得、按钮先于对应桥、钥匙先于对应门，以及传送出口方向正确。用错误布局验证失败位置和原因。改变总关数时，同时更新 UI 总数、章节导航、存档清洗与测试断言。

当前自动测试验证可解性和规则；儿童实际游玩时长、直观程度和兴趣仍需要试玩观察。
